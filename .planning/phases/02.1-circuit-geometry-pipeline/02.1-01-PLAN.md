<objective>
Replace hand-authored non-closing x/y circuit coordinates with real geometry from TUMFTM (Monza, Silverstone) and bacinger/f1-circuits GeoJSON (Monaco). Create a reproducible Python pipeline script so future circuits do not require hand-authoring.

Purpose: The current x/y coordinates were derived by integrating hand-authored curvature, producing shapes that do not close (2km+ gap) and are not visually recognizable as the actual circuits. TUMFTM provides GPS-derived centerlines at ~5m spacing; bacinger provides Monaco at lower resolution (~21m). Both produce recognizable track outlines.

Output: Updated circuit preset JSON files with accurate x/y, a reusable pipeline script, and cached source data files.
</objective>

- Silverstone CSV: `https://raw.githubusercontent.com/TUMFTM/racetrack-database/master/tracks/Silverstone.csv`
- Monaco GeoJSON: `https://raw.githubusercontent.com/bacinger/f1-circuits/master/circuits/mc-1929.geojson`

Download using `urllib.request` or `curl`. Cache these files in `presets/circuits/sources/` so the pipeline can run offline. Commit the source files as build inputs (they are small, <100KB each, and provide data provenance).

**Create `scripts/build-circuit-geometry.py`** with the following structure:

1. **CLI interface:** Accept `--circuit {monza|monaco|silverstone}` or `--all`. Print a summary for each circuit (point count, arc length, closure gap, bounding box).

2. **TUMFTM CSV parser:** Read CSV with header `# x_m,y_m,w_tr_right_m,w_tr_left_m`. Extract x_m and y_m columns. The comment-prefixed header line starts with `# `. Parse accordingly.

3. **bacinger GeoJSON parser:** Read GeoJSON, extract coordinates from `features[0].geometry.coordinates`. Drop the duplicate closing point (coords[0] == coords[-1]). Project to local meters using equirectangular projection:
   ```
   lat_ref = mean of all latitudes
   lon_ref = mean of all longitudes
   R = 6_371_000
   x = R * radians(lon - lon_ref) * cos(radians(lat_ref))
   y = R * radians(lat - lat_ref)
   ```

4. **Periodic spline fitting:** For both sources:
   - Close the loop by appending the first point as the (N+1)th point
   - Fit periodic cubic B-spline: `splprep([x, y], s=0, per=True, k=3)`
   - Compute total arc length from the closed input polyline
   - Determine output point count: `n_out = round(total_arc_length / 5)`
   - Evaluate at uniform parameter: `linspace(0, 1, n_out, endpoint=False)`
   - Compute output distance array: `linspace(0, total_arc_length, n_out, endpoint=False)`

5. **Curvature re-indexing:** Load the existing preset JSON. Extract the existing curvature array. Re-index to the new distance array using `numpy.interp` with periodic wrapping:
   ```python
   old_distances = [p['distance'] for p in existing_points]
   old_curvatures = [p['curvature'] for p in existing_points]
   old_total = existing_doc['totalLength']
   # Normalize both to [0, 1] to handle different total lengths
   old_norm = [d / old_total for d in old_distances]
   new_norm = [d / new_total for d in new_distances]
   new_curvatures = np.interp(new_norm, old_norm, old_curvatures, period=1.0)
   ```

6. **Sector and corner distance re-mapping:** Scale proportionally:
   ```python
   scale = new_total_length / old_total_length
   for sector in doc['sectors']:
       sector['startDistance'] = round(sector['startDistance'] * scale)
       sector['endDistance'] = round(sector['endDistance'] * scale)
   for corner in doc['corners']:
       corner['apexDistance'] = round(corner['apexDistance'] * scale)
       corner['entryDistance'] = round(corner['entryDistance'] * scale)
       corner['exitDistance'] = round(corner['exitDistance'] * scale)
   ```
   Ensure the last sector's endDistance equals the new totalLength (round to int).

7. **Provenance update:** Update the `provenance` field per circuit:
   - Monza/Silverstone: `sourceType: "documented-fact"`, `source: "TUMFTM racetrack-database (LGPL-3.0), GPS centerlines from OpenStreetMap"`, `notes: "x/y from TUMFTM ~5m spacing, curvature hand-authored from published corner radii, distances re-indexed proportionally"`
   - Monaco: `sourceType: "documented-fact"`, `source: "bacinger/f1-circuits (MIT), GeoJSON centerline with equirectangular projection"`, `notes: "x/y from bacinger ~21m spacing resampled to 5m via periodic spline, curvature hand-authored from published corner radii, distances re-indexed proportionally. Lower resolution than TUMFTM; tight corners appear rounder than reality."`

   Update assumptionNotes: replace the second note about x/y being "integrated from curvature" with a note about x/y being "derived from GPS centerline data" referencing the actual source. Keep the first note about curvature being from published corner radii.

8. **Output:** Build the full CircuitDocument JSON structure (preserving schemaVersion, circuitId, name, configuration, corners, sectors from existing). Write with `json.dump(..., indent=2)` and a trailing newline. Round x/y to 2 decimal places, curvature to 6 decimal places, distance to integer (matching existing convention from generate-circuits.ts -- actually distance in existing files is integer multiples of 5, so use `round(d)` for distances).

9. **Sanity print:** For each circuit, print: circuit name, point count, arc length, closure gap (distance from last point to first point), bounding box (min/max x, min/max y).

**Important constraints:**
- Do NOT re-derive curvature from GPS data. GPS noise produces implausible corner radii (R=10m where reality is 45m). Keep existing hand-authored curvature per research decision.
- Do NOT append a duplicate closing point to output. The schema convention is open-array: points at distances 0, 5, 10, ..., L-5. The track closes by wrapping last->first.
- Use `s=0` for splprep (interpolating, not smoothing) per research recommendation.
- The bacinger Monaco GeoJSON `it-1953.geojson` is Imola, NOT Monza. Monaco is `mc-1929.geojson`.
- Use only numpy, scipy, json, csv, math, urllib.request, os, argparse -- all available in base Python.
