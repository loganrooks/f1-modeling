**Create `packages/sim-core/src/raceModel/pitModel.ts`:**

Implement the reduced-order pit-lane loss model from RESEARCH.md:

```
L_pit = (t_entry + t_exit - t_bypass) + t_stop
```

1. `computePitLoss(params: PitLaneParams, discountFactor?: number): PitLossResult`
   - traversalDelta = (params.pitEntryTime + params.pitExitTime) - params.pitBypassTime
   - totalLoss = (traversalDelta + params.serviceTime) * (discountFactor ?? 1.0)
   - Return { totalLoss, traversalDelta, serviceTime: params.serviceTime }
   - The discountFactor is applied to the TOTAL loss (under VSC/SC conditions, everything is cheaper because the field is slower)
   - Add provenance comment: "Source: Race strategy modelling literature (Heilmeier et al., formula1.wiki)"

2. `DEFAULT_PIT_LANE_PARAMS: PitLaneParams` -- generic circuit defaults:
   - pitEntryTime: 12 (seconds)
   - pitExitTime: 10 (seconds)
   - pitBypassTime: 4 (seconds)
   - serviceTime: 2.5 (seconds)
   - These produce a ~20.5s green-flag pit delta. Add provenance comment: "Engineering-inference from published circuit data. Typical range: 18-25s."

**Create `packages/sim-core/src/raceModel/interruptionModel.ts`:**

Implement interruption effects for the single-car model from RESEARCH.md:

1. `interruptionLapTimeFactor(type: InterruptionType): number`
   - "vsc": 1.30 (30% slower than racing pace)
   - "sc": 1.40 (40% slower)
   - "red-flag": Infinity (session stopped)
   - Add provenance comment.

2. `pitLossDiscountFactor(type: InterruptionType): number`
   - "vsc": 0.65 (35% reduction in pit loss)
   - "sc": 0.40 (60% reduction)
   - "red-flag": 0.0 (free tire change)
   - Add provenance comment.

3. `applyInterruptionsToLapTimes(lapTimes: number[], interruptions: InterruptionSpec[], raceStartLap: number): number[]`
   - Takes an array of stint-local lap times and returns a modified copy with interruption effects applied.
   - For each interruption, map race-level laps to stint-local laps: `stintLocalLap = interruptionLap - raceStartLap`.
   - For laps within the interruption range, replace lapTime with `lapTime * interruptionLapTimeFactor(type)`.
   - For red-flag: laps within the range get set to 0 (session stopped -- race distance adjustment is the caller's responsibility).
   - Return a NEW array (do not mutate input). This is critical for the race engine to compare original vs. modified times.

**Create `packages/sim-core/src/raceModel/raceRunner.ts`:**

Implement `runRace(stints: StintSpec[], config: RaceConfig, interruptions?: InterruptionSpec[]): RaceResult`

The race engine is a thin orchestration layer that:

1. **Initializes race state** from the first stint's configuration:
   - Call `initializeStintState()` with the first stint's compound and policy to get the starting StintState.
   - Set raceStartLap = 0.

2. **Iterates over each stint** in order:
   a. Build a `StintConfig` from the current `StintSpec` + `RaceConfig`:
      - circuit, baseVehicle, weatherTimeline, aeroConfig, loadTransferParams from RaceConfig
      - tireCompound, electricalPolicy, totalLaps from StintSpec
      - ambientTemperatureC from RaceConfig
   b. For the first stint: call `runStint(stintConfig)` (fresh initialization).
      For subsequent stints: call `runStintFromState(stintConfig, currentState)` where `currentState` is the pit-modified state from the previous stint.
   c. Record stint-start timeline event.
   d. If interruptions are provided, call `applyInterruptionsToLapTimes()` on the stint's lap times. The race engine RECORDS the interruption timeline events but the actual lap-time modification happens via `applyInterruptionsToLapTimes()`. Note: in this reduced-order model, interruptions modify the final lap times in the result. The stint runner ran with racing-pace physics; the interruption model adjusts the resulting times to account for slow laps.
   e. Accumulate stint time (sum of possibly-modified lap times) into cumulative race time.
   f. Record stint-end timeline event with summary metrics (stintTime, cumulativeRaceTime, finalTireWear, finalSoC, effectiveGripRange).
   g. If NOT the last stint, apply pit event:
      - Compute pit loss via `computePitLoss(config.pitLaneParams)`. If an interruption is active at the pit lap, apply the corresponding discount factor.
      - Add pit loss to cumulative race time.
      - Mutate state for next stint: fresh tires for the next compound, electrical state carries through (SoC persists across pit stops), environment state carries through, fuel state persists (no refueling in 2026 regulations).
      - Record pit-event timeline event.
   h. Record interruption-start and interruption-end timeline events at the correct race laps.
   i. Update raceStartLap for the next stint.

3. **Build RaceResult:**
   - stintResults: all collected StintResult objects
   - timeline: chronologically ordered RaceTimelineEvent array
   - totalRaceTime: sum of all stint times + all pit losses
   - totalPitTime: sum of all pit losses
   - stintSummaries: per-stint { stintIndex, compound, laps, stintTime, finalWear, finalSoC }
   - assumptions: merge stint assumptions + race-level assumptions (pit-loss model, interruption model, single-car limitation)

4. **Pit-event state mutation** (inline helper or separate function):
   ```
   applyPitEvent(finalState, nextStintSpec, trackTemp):
     tireState = initializeTireState(nextStintSpec.tireCompound, trackTemp) // fresh tires
     electricalState = finalState.electricalState // SoC carries through
     environmentState = finalState.environmentState // weather carries through
     fuelMass = finalState.fuelMass // no refueling
     lapNumber = finalState.lapNumber
   ```
   Use `initializeTireState()` from the tire model (already exported) to get fresh tire state for the new compound.

5. **Race-level assumptions array** must include:
   - "Race-state engine: thin orchestration over existing stint runner"
   - "Pit-lane loss: L_pit = (t_entry + t_exit - t_bypass) + t_stop (engineering-inference)"
   - "Single-car model: no opponent field, traffic, or overtaking"
   - "Interruptions: lap-time multipliers and pit-cost discounts (engineering-inference)"
   - "No refueling: 2026 regulations (fuel state carries through pit stops)"

**Timeline event ordering:** Events must be in chronological order by raceLap. Within a single raceLap, order: interruption-start (if any) before stint-start/stint-end, pit-event after stint-end, interruption-end after everything else at that lap.
