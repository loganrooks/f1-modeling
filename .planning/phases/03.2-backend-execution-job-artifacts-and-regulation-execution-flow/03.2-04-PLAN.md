<doctrine_alignment>

## Vision Impact

This plan resolves **`VA-TD-01`** — splitting `runService.ts` into compiler / backend-adapter / persistence concerns. This is the central long-arc move that makes "compute can later move between local-worker, sidecar, and remote backends" (LONG-ARC § Protected Seams 1) a structural reality rather than aspiration. Without this split, the file remains the architectural debt that locks the product to one execution topology.

Concretely:

- `runService.ts` becomes a thin orchestration shell, not a god-service.
- `runCompiler.ts` (from plan 01) owns request shaping.
- `localSimulationBackend.ts` owns execution dispatch behind the `SimulationBackend` interface.
- Persistence concerns route through the artifact/run stores from plan 03.
- Existing lap, stint, and race execution behaviors landed in Phase 3/3.1 remain compatibility obligations during the split — silent breakage is a regression, not a refactor.

## Honesty Surface

- The completion path records `fidelityTier` and `validationState` faithfully — never inferred from "test passed" to "result is calibrated."
- Error envelopes from the backend propagate without rephrasing. The consumer sees the real failure.
- Async-job state transitions are recorded in the artifact lineage so a future reader can audit "what stage failed and why."

## Performance Budget

Refactor — not a perf change. Performance obligation is **regression-bounded**, not improvement-required:

- Existing test latencies (`apps/local-api/src/__tests__/raceRuns.test.ts`, lap/stint route tests) must stay within ±10% of pre-split baseline.
- Plan SUMMARY records before/after timing for the race-run integration test as the canonical comparable workload.
- Memory: the split should not introduce avoidable copies between compiler → backend → persistence. References, not clones.

</doctrine_alignment>

   - `fetchArtifact`
