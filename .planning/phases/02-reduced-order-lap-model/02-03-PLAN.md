**SpeedProfileTrace (packages/visuals/src/traces/SpeedProfileTrace.tsx):**

A speed-vs-distance SVG chart extending the MetricTracePanel pattern.

Props interface `SpeedProfileTraceProps`:
- `profile: SpeedProfilePoint[]` -- the speed profile data.
- `sectors?: { sectorIndex: number, sectorName: string, startDistance: number, endDistance: number }[]` -- optional sector boundary annotations.
- `circuitName: string` -- displayed as chart title.
- `comparisonProfile?: SpeedProfilePoint[]` -- optional second profile for overlay comparison (shown as dashed line).
- `comparisonLabel?: string` -- label for the comparison profile.
- `width?: number` (default 800), `height?: number` (default 300).

Implementation:
1. Compute SVG viewport from the data: x-axis = distance (0 to max), y-axis = speed (0 to max speed * 1.1 for headroom). Add axis labels: "Distance (m)" and "Speed (km/h)" (convert m/s to km/h for display: `speed * 3.6`).
2. Draw the primary speed profile as a SVG `<polyline>` or series of `<line>` segments, colored by regime:
   - `"accelerating-grip"` and `"accelerating-power"`: green shades (`#22c55e` for grip, `#16a34a` for power).
   - `"braking"`: red (`#ef4444`).
   - `"cornering"`: amber (`#f59e0b`).
3. If `comparisonProfile` is provided, draw it as a dashed gray polyline overlaid on the same axes.
4. Draw sector boundaries as vertical dashed lines with sector name labels at the top.
5. Add a legend showing regime colors.
6. Add a simple tooltip behavior: on mouseover of a data point region, show distance, speed (km/h), regime, lateral G, and longitudinal G in a small overlay. Use React state for hover position, not an external tooltip library.

Use inline styles consistent with the project (no CSS modules, no Tailwind). The SVG should be responsive: use `viewBox` with the specified width/height and set the SVG element to `width="100%"`.

**TrackMap (packages/visuals/src/workspace/TrackMap.tsx):**

An SVG track outline with speed-colored overlay.

Props interface `TrackMapProps`:
- `points: { x: number, y: number, speed: number, regime: string }[]` -- merged circuit spatial + speed profile data.
- `circuitName: string`.
- `sectors?: { sectorName: string, startDistance: number }[]`.
- `provenance: { sourceType: string, source: string, notes: string }` -- displayed as honesty label.
- `width?: number` (default 400), `height?: number` (default 400).
- `noSpatialData?: boolean` -- if true, renders the existing `TrackContextPlaceholder` instead.

Implementation:
1. If `noSpatialData` is true or points have no x/y data, render `TrackContextPlaceholder` with a message "No spatial coordinates available for this circuit. Speed-vs-distance trace shown instead."
2. Otherwise: compute SVG viewport from x/y bounds with padding. Normalize coordinates to fit within the viewBox.
3. Draw the track outline as a series of `<line>` segments between consecutive points, each colored by the speed at that point using a blue-to-red gradient (slow = blue, fast = red). Use a continuous color scale: `hsl(240 - speed/maxSpeed * 240, 80%, 50%)` maps blue (slow) through green/yellow to red (fast).
4. Add a small color legend bar showing the speed range.
5. Draw sector start indicators as small circles or ticks on the track outline.
6. Display the provenance label at the bottom of the component in small italic text: "Track outline: {provenance.source}. {provenance.notes}".
7. Add a start/finish indicator (small marker at the first point).

The track outline should be recognizable as the correct circuit shape. It does NOT show a racing line -- just the center-line track shape with speed-colored segments.

**SensitivityWaterfall (packages/visuals/src/inspectors/SensitivityWaterfall.tsx):**

A waterfall/bridge chart showing how sector-by-sector time deltas add up to the total lap time difference.

Props interface `SensitivityWaterfallProps`:
- `baselineSectors: SectorResult[]` -- sector results from baseline run.
- `modifiedSectors: SectorResult[]` -- sector results from modified run.
- `baselineLabel: string` -- e.g., "Baseline (798 kg)".
- `modifiedLabel: string` -- e.g., "Modified (878 kg)".
- `totalBaselineTime: number` -- baseline lap time.
- `totalModifiedTime: number` -- modified lap time.
- `width?: number` (default 700), `height?: number` (default 350).

Implementation:
1. For each sector, compute `delta = modifiedSectors[i].sectorTime - baselineSectors[i].sectorTime`. Positive delta = sector is slower in modified run. Negative = faster.
2. Build a waterfall chart: horizontal axis = sectors (labeled by sectorName), vertical axis = cumulative time delta. Each bar starts from the running cumulative and extends up (slower, red `#ef4444`) or down (faster, green `#22c55e`).
3. Start with a "Baseline" bar at 0. End with a "Total" bar showing the cumulative delta, colored by whether the total is positive or negative.
4. Label each bar with the delta value (e.g., "+0.15s" or "-0.08s").
5. Below each sector bar, show the `limitingFactor` from the sector with the larger absolute delta.
6. Add axis labels and a title: "Lap Time Sensitivity: {baselineLabel} vs {modifiedLabel}".

Use the same inline SVG style patterns as SpeedProfileTrace.
