## Mandatory Phase Lifecycle (do not skip steps)

Each phase MUST follow this exact sequence. Do not auto-advance to the next phase
without completing every step. Clear context between major steps to keep context
windows fresh and agent quality high.

### Step 1: Plan the phase
- Run the plan-phase workflow for the current phase number.
- This automatically invokes: research agent, planner agent, plan-checker agent.
- All three quality gates (research, plan_check, verifier) are enabled in config.
- Do NOT skip research — every phase has material open questions that research resolves.
- The plan-checker validates the plan against the phase goal before proceeding.
- Clear context after planning completes.

### Step 2: Execute the phase
- Run the execute-phase workflow for the current phase number.
- This handles wave-based parallelization of plans within the phase.
- Each plan produces atomic commits — no uncommitted work between plans.
- The executor writes SUMMARY.md for each completed plan.
- If a plan fails or encounters blockers, pause and assess rather than forcing through.
- Clear context after execution completes.

### Step 3: Verify the phase
- Run the verify-work workflow for the completed phase.
- This is user acceptance testing — checks that what was built actually meets the phase's
  success criteria, not just that tasks completed.
- Creates VERIFICATION.md or UAT.md with pass/fail per criterion.
- If gaps are found (status: diagnosed), do NOT advance. Instead route to plan-phase
  with --gaps flag to create fix plans, then re-execute and re-verify.
- Clear context after verification completes.

### Step 4: Collect signals
- Run the collect-signals workflow for the completed phase.
- This analyzes execution artifacts (PLANs, SUMMARYs, VERIFICATION) and git history
  using parallel sensor agents, then synthesizes signals into the knowledge base.
- Captures lessons, patterns, and drift indicators for future phases.
- Skip only if the phase was trivial (1-2 plans, no surprises).

### Step 5: Check progress and route
- Run the progress workflow to get situational awareness and routing.
- This shows overall milestone progress and routes to the next action.
- If the next phase has context (CONTEXT.md exists), it routes to plan-phase.
- If not, it routes to discuss-phase first to gather context.
- Follow the routing — do not skip discuss-phase when context is missing.

### Step 6: Discuss the next phase (if no CONTEXT.md)

  questions before planning.
