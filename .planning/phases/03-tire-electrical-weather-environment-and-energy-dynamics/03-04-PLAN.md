  <action>
    Create three test files using vitest (the project's test framework). Import from the stintModel package exports.

    **tireModel.test.ts** -- Test tire subsystem in isolation:

    1. **Degradation curves differ by compound**: Run `updateTireState()` for 30 laps with soft, medium, and hard compounds. Assert soft wearFraction > medium > hard at every 5-lap checkpoint. Assert the soft tire reaches cliffThreshold before hard.

    2. **Cliff behavior**: Start a soft tire at wearFraction = 0.68 (just below cliffThreshold 0.70). Run 10 more laps. Assert that `tireWearGripFactor()` drops much faster after crossing the threshold. Quantitatively: grip factor at wear 0.80 should be at least 15% lower than the linear trend would predict.

    3. **Thermal window**: Test `tireThermalFactor()` at temperatures inside the window (returns 1.0), below the window (returns < 1.0), and above the window (returns < 1.0). Assert the floor of 0.5 holds even at extreme temperatures (0C, 200C).

    4. **Warm-up dynamics**: Initialize tire at 20C (cold). Run 5 laps. Assert surface temperature increases toward the compound's optimal range. Verify core temperature lags behind surface temperature.

    5. **Grip floor**: Test that `tireWearGripFactor()` never returns below 0.3 even at wearFraction = 1.0.

    Use a mock LapModelOutput for `updateTireState()`: create a minimal object with a few SpeedProfilePoint entries that have representative speed, lateralG, longitudinalG values. The tire model only needs average speed for thermal dynamics, which can be derived from the profile.

    **electricalModel.test.ts** -- Test electrical subsystem in isolation:

    1. **SoC bounded**: Run 50 laps with aggressive deployment. Assert SoC never goes below 0. Run 50 laps with no deployment (deployFraction = 0). Assert SoC never exceeds maxCapacity.

    2. **Harvest from braking**: Create a mock LapModelOutput with braking segments (negative longitudinalG). Assert `estimateBrakingEnergy()` returns a positive value proportional to the braking intensity.

    3. **Harvest cap**: Assert that harvested energy per lap never exceeds `policy.maxHarvestPerLap` (8.5 MJ).

    4. **Policy comparison**: Run the same 20-lap stint with aggressive (deployFraction 0.7) and conservative (deployFraction 0.35) policies. Assert:
       - Aggressive: higher total deployed energy, lower final SoC.
       - Conservative: lower total deployed energy, higher final SoC.
       - Both policies result in non-negative SoC at all laps.

    5. **Power modifier**: Assert `computeElectricalPowerModifier()` returns higher effective power when SoC is high + aggressive policy, and lower when SoC is depleted.

    6. **Environment-aware harvesting (cross-subsystem coupling)**: Call `updateElectricalState()` with the same lapResult and policy but two different EnvironmentState values:
       - Dry: `{ surfaceWetness: 0.0, trackTemperatureC: 33, rubberEvolution: 1.0, gripModifier: 1.0 }`
       - Wet: `{ surfaceWetness: 0.7, trackTemperatureC: 18, rubberEvolution: 0.95, gripModifier: 0.6 }`
       Assert that the wet case produces LESS harvested energy than the dry case (the `1 - 0.2 * surfaceWetness` penalty reduces effective harvest efficiency). Quantitatively: wet harvest should be approximately `0.86x` of dry harvest (1 - 0.2 * 0.7 = 0.86). Also test with `environmentState: undefined` and confirm it matches the dry case (no penalty applied).

    **environmentModel.test.ts** -- Test environment subsystem in isolation:

    1. **Weather interpolation**: Create a timeline with events at laps 0, 10, and 20. Assert `interpolateWeatherAtLap(timeline, 5)` returns values halfway between lap 0 and lap 10 events. Assert boundary values: lap 0 = first event, lap 20 = last event.

    2. **Surface grip factor**: Assert `surfaceGripFactor(0.0)` = 1.0 (dry). Assert `surfaceGripFactor(0.5)` is approximately 0.775. Assert `surfaceGripFactor(1.0)` >= 0.55 (floor).

    3. **Rubber evolution buildup**: Start at rubberEvolution 0.95. Run 20 dry laps. Assert rubber increases toward 1.05 but never exceeds it.

    4. **Rain washout**: Build rubber to 1.03 over dry laps. Then apply rain (surfaceWetness 0.7). Assert rubber drops back toward 0.95.

    5. **Combined grip modifier**: Run a dry-to-wet transition (dry for 10 laps, then wet). Assert gripModifier decreases when rain arrives. Assert the magnitude of grip change is physically plausible (not > 50% drop in one lap).

    All tests should use `describe()` blocks grouped by concern. Use `expect(x).toBeCloseTo(y, precision)` for floating-point comparisons. Use `expect(x).toBeGreaterThan(y)` and `expect(x).toBeLessThan(y)` for inequality assertions.
  </action>

    2. **Compound comparison**: Run 15-lap stints on the same circuit with soft, medium, and hard compounds. Assert:
       - Soft has fastest first lap but fastest degradation.
       - Hard has slowest first lap but least degradation.

    3. **Energy policy comparison (success criterion 2)**: Run 15-lap stints with aggressive vs conservative electrical policy on the same circuit/tire. Assert:
       - Aggressive: lower early lap times (more power deployed).

       - Both stints complete without errors.
       - The lap time difference between policies is observable (at least 0.1s on some laps).

       - Lap times increase when rain arrives (grip drops).
       - Environment state shows surfaceWetness > 0 during rain laps.
       - Effective grip (from LapTrace) drops during wet conditions.
       - Lap times recover if weather dries.

       - Stint A: dry weather (surfaceWetness 0 throughout)
       - Stint B: wet weather (surfaceWetness 0.6 throughout)
       Assert that Stint B has lower cumulative harvested energy than Stint A (proving the environmentState->updateElectricalState coupling produces measurable SoC differences). The difference should be approximately proportional to `1 - 0.2 * 0.6 = 0.88` (12% reduction in harvesting).

       - Lap times remain within 2x of a dry baseline lap time.
       - Effective grip never goes below 0.4.
