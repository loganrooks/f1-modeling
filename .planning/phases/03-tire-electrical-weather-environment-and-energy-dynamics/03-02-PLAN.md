    **stintModel/electricalModel.ts** -- Implement the lap-level energy balance model. Import types from "./types.js" and SpeedProfilePoint/LapModelOutput from "../lapModel/types.js".

    1. `initializeElectricalState(policy: ElectricalPolicy): ElectricalState` -- Creates initial state: SoC at maxCapacity (default 4_000_000 J = 4 MJ delta SoC per 2026 regs), all counters at 0. maxCapacity should come from a regulation constant or be derivable from policy context. Use 4_000_000 as default.

    2. `estimateBrakingEnergy(lapResult: LapModelOutput, vehicleMass: number): number` -- Estimates recoverable braking energy from the solved speed profile. Iterate through speedProfile points: where longitudinalG < 0 (braking), compute kinetic energy delta = 0.5 * mass * (v_prev^2 - v_current^2) for each braking segment. Sum all braking energy. This gives total dissipated energy during braking -- the harvest fraction is applied separately. Use timeIncrement and speed fields.

    3. `updateElectricalState(prev: ElectricalState, lapResult: LapModelOutput, policy: ElectricalPolicy, vehicleMass: number): ElectricalState` -- Per-lap energy update following RESEARCH.md pattern:
       - Harvest: `min(estimateBrakingEnergy(lapResult, vehicleMass) * policy.harvestEfficiency, policy.maxHarvestPerLap)`.
       - Deploy: `min(prev.stateOfCharge * policy.deployFraction, prev.maxCapacity)`. This is the energy consumed from the battery this lap.
       - New SoC: `clamp(prev.stateOfCharge + harvest - deploy, 0, prev.maxCapacity)`.
       - Return updated state with per-lap and cumulative counters.

    4. `computeElectricalPowerModifier(electricalState: ElectricalState, policy: ElectricalPolicy, basePeakPower: number): number` -- Returns the effective peak power including electrical deployment. If SoC > 0 and policy allows deployment: `basePeakPower + min(policy.maxDeployPower, availableDeployRate)` where availableDeployRate is derived from the energy available to deploy this lap spread across the lap time. However, for simplicity at this fidelity: return `basePeakPower * (1 + deployBoostFraction)` where deployBoostFraction is proportional to `policy.deployFraction * (electricalState.stateOfCharge / electricalState.maxCapacity)`. Scale so that at full SoC with aggressive deploy, effective power = basePeakPower + policy.maxDeployPower. At empty SoC, effective power = basePeakPower (ICE only). Cap total power at basePeakPower + policy.maxDeployPower. The research says 2026 total system power is ~750 kW (400 kW ICE + 350 kW MGU-K).

    Define regulation constants at the top of the file with provenance comments:
    ```typescript
    // 2026 FIA PU Technical Regulations reference values
    // Source: Honda commentary + FIA Issue 7, provenance: engineering-inference
    const REGULATION_2026 = {
      maxMguKPower: 350_000,       // 350 kW
      maxHarvestPerLap: 8_500_000, // 8.5 MJ
      maxDeltaSoC: 4_000_000,      // 4 MJ usable energy window
      icePower: 400_000,           // ~400 kW ICE (engineering estimate)
    };
    ```

    Also export a `DEFAULT_AGGRESSIVE_POLICY` and `DEFAULT_CONSERVATIVE_POLICY`:
    - Aggressive: deployFraction 0.7, harvestEfficiency 0.85, maxDeployPower 350_000, maxHarvestPerLap 8_500_000.
    - Conservative: deployFraction 0.35, harvestEfficiency 0.85, maxDeployPower 350_000, maxHarvestPerLap 8_500_000.

    **stintModel/aeroModel.ts** -- Implement aero-mode pre-processing. Import types from "./types.js" and CircuitLayoutPoint from "../lapModel/types.js".

    1. `AeroResolvedPoint` type (or re-export from types if defined there): distance, curvature, dragFactor, downforceFactor, aeroMode ("corner-mode" | "straight-mode").

    2. `resolveAeroPerPoint(circuit: CircuitLayoutPoint[], aeroConfig: AeroModeConfig): AeroResolvedPoint[]` -- Maps each circuit point to its aero state based on whether the point's distance falls within any straightModeZone. Follow RESEARCH.md Pattern exactly. Points inside a zone get straight-mode drag/downforce; points outside get corner-mode values.

    3. `computeAverageAeroFactors(resolvedPoints: AeroResolvedPoint[]): { avgDragFactor: number; avgDownforceFactor: number }` -- Distance-weighted average of drag and downforce factors across the circuit. This gives a single representative set of aero factors for the StintRunner to feed into VehicleParams. This is a simplification -- the per-point resolution is available for future per-segment solving but for now the solver takes a single VehicleParams per lap.

    Export all functions and the AeroResolvedPoint type.
